# 执行阶段插件

本插件定义了CRCT系统的执行阶段的操作流程和规则。

## I. 执行阶段概述

执行阶段是CRCT系统的实施阶段，负责：

1. **任务执行**：按照指令文件执行任务
2. **代码实现**：编写、修改和测试代码
3. **文档更新**：更新项目文档
4. **验证和测试**：验证任务完成并进行测试
5. **状态跟踪**：跟踪任务执行状态和进度

## II. 执行阶段工作流程

1. **读取`.clinerules`**：确定当前阶段和上一次操作
2. **加载指令文件**：读取当前任务的指令文件
3. **检查依赖关系**：确保所有依赖任务已完成
4. **执行任务步骤**：按照指令文件中的步骤执行任务
5. **验证结果**：验证任务完成并满足成功标准
6. **更新系统状态**：遵循强制更新协议(MUP)更新系统状态
7. **处理子任务**：如果出现子任务，创建新的指令文件并递归处理
8. **完成任务**：标记任务为已完成并更新相关文档

## III. 任务执行和验证

### 任务执行原则

1. **遵循指令**：严格按照指令文件中的步骤执行任务
2. **增量执行**：逐步执行任务，每一步都验证结果
3. **错误处理**：及时处理执行过程中的错误和异常
4. **文档同步**：保持代码和文档的同步更新
5. **依赖管理**：确保依赖关系得到正确处理

### 任务验证步骤

1. **功能验证**：验证任务的功能是否符合要求
2. **代码质量**：检查代码质量，包括可读性、可维护性和性能
3. **测试覆盖**：确保有足够的测试覆盖
4. **文档完整性**：验证文档是否完整和准确
5. **依赖一致性**：确保依赖关系的一致性

## IV. 代码实现和修改

### 代码实现原则

1. **清晰简洁**：编写清晰、简洁的代码
2. **模块化**：遵循模块化原则，保持代码的高内聚低耦合
3. **可测试性**：确保代码易于测试
4. **错误处理**：妥善处理错误和异常情况
5. **性能考虑**：考虑代码的性能影响

### 代码修改步骤

1. **理解现有代码**：在修改前充分理解现有代码
2. **制定修改计划**：制定明确的修改计划
3. **增量修改**：逐步进行修改，每一步都验证结果
4. **更新测试**：更新或添加测试以覆盖修改
5. **文档更新**：更新相关文档以反映修改

## V. 执行阶段的强制更新协议(MUP)

除了核心MUP步骤外，执行阶段还需要执行以下特定步骤：

1. **更新`.clinerules`**：
   - 更新`[LAST_ACTION_STATE]`部分
   - 添加到`[LEARNING_JOURNAL]`部分

2. **更新`activeContext.md`**：
   - 记录当前执行操作的状态
   - 记录已完成的任务步骤
   - 记录遇到的问题和解决方案

3. **更新`changelog.md`**：
   - 记录代码修改和文件变更
   - 记录重要的实现决策

4. **更新指令文件**：
   - 标记已完成的步骤
   - 更新任务状态

5. **更新依赖关系跟踪器**：
   - 使用`dependency_processor.py`更新依赖关系跟踪器
   - 记录新发现的依赖关系

## VI. 子任务处理

在执行任务过程中，可能会发现需要创建和处理子任务。

### 子任务创建步骤

1. **识别子任务**：确定需要创建子任务的情况
2. **创建指令文件**：为子任务创建详细的指令文件
3. **设置依赖关系**：确定子任务与父任务的依赖关系
4. **递归处理**：递归处理子任务

### 子任务合并步骤

1. **验证子任务完成**：确保所有子任务都已完成
2. **合并结果**：将子任务的结果合并到父任务中
3. **更新状态**：更新父任务的状态
4. **文档更新**：更新相关文档以反映子任务的完成

## VII. 任务完成和收尾

### 任务完成标准

1. **功能完整**：所有功能都已实现并符合要求
2. **测试通过**：所有测试都已通过
3. **文档完整**：所有文档都已更新和完善
4. **代码质量**：代码质量符合项目标准
5. **依赖处理**：所有依赖关系都已正确处理

### 任务收尾步骤

1. **最终验证**：进行最终的验证和测试
2. **更新指令文件**：将任务标记为已完成
3. **更新系统状态**：执行完整的MUP
4. **准备下一个任务**：准备执行下一个任务或返回策略阶段

## VIII. 执行阶段的命令执行指南

在执行阶段，需要执行各种命令来实现任务目标。

### 命令执行原则

1. **预先验证**：在执行命令前验证文件系统状态
2. **增量执行**：逐步执行命令，每一步都验证结果
3. **错误处理**：妥善处理命令执行失败的情况
4. **文档记录**：记录重要命令的执行结果
5. **状态更新**：执行命令后更新系统状态

### 常用命令类型

1. **文件操作**：创建、修改、删除文件
2. **代码编译**：编译代码
3. **测试执行**：运行测试
4. **依赖管理**：管理项目依赖
5. **版本控制**：执行版本控制操作
